## particle_filter: 오도메트리 이동량 계산 (11/24, v4)

### 문제
`pose_source:=pf` 로 달리면 1바퀴 안에 벽에 부딪혔다. 기록을 보면 충돌 직전마다 파티클 필터 위치가 1.5~11 m 순간이동했고,
그 직전에 EKF 오도메트리(`/early_fusion/odom`)가 먼저 6~16 m 튀었다.
원래 `odomCB` 는 연속된 두 EKF **위치**의 차이를 모든 파티클의 이동량으로 써서, EKF 가 튀면 필터 전체가 같이 순간이동했다.

### 원인
- 시뮬레이터(gym_bridge)와 모든 노드는 시스템 시계로 메시지 시각(stamp)을 찍는다 (`use_sim_time` 없음).
- 개인 PC(Windows + WSL2)에서는 **아무것도 안 돌릴 때도 시스템 시계가 약 32초마다 2.94초씩 앞으로 점프했다**
  (같은 순간 monotonic 시계는 10 ms 만 흐름 — 컨테이너 밖 WSL 에서 측정). 시뮬 속 차는 그대로인데 메시지 시각만 2.94초 건너뛴다.
- EKF 는 다음 측정까지의 시각 차이(2.94 s)만큼 마지막 속도로 위치를 외삽해서 한 번에 6.4 m, 8.2 m, 13 m 씩 튀었다.
  방향도 각속도 x 2.94 s 만큼 튀었다가 다음 메시지에서 돌아온다.
- 이와 별개로 CPU 가 바쁘면 EKF 자체가 ~0.35 s 씩 멈춘다 ("Failed to meet update rate"). 이때는 시뮬 속 차가 실제로 움직였다.
  `/car_state/odom` 은 EKF 메시지가 올 때만 나오므로 pf 든 gt 든 컨트롤러가 받는 위치도 같이 멈춘다.
- 학교 PC(우분투 직접 설치)에서는 같은 측정으로 시계 점프가 있는지 확인이 필요하다. 없더라도 아래 수정은 해가 없다.

### 고친 것 (`odom_motion: velocity`, 기본값)
1. 이동 거리는 EKF 위치 차이 대신 **EKF 속도 x 메시지 간격**으로 계산한다 (호(arc) 모양, 방향 변화 = EKF 방향 변화).
   EKF 방향 변화가 각속도 x 간격과 0.3 rad 이상 다르면 각속도 x 간격을 쓴다.
2. **시계 점프 감지**: 메시지 시각 차이가 실제로 메시지를 받은 간격(monotonic 시계)보다 `odom_clock_jump`(1.0 s) 넘게 크면
   시계가 점프한 것으로 보고 받은 간격을 쓴다. 경고 로그 `system clock jump #N`.
   (0.25 s 로 했더니 EKF 의 진짜 0.36 s 멈춤을 시계 점프로 잘못 판단한 적이 있어 1.0 s 로 올림. WSL 점프는 2.9 s)
3. **진짜 공백**: 그래도 간격이 `odom_gap_dt`(0.5 s, 평소 0.02 s) 보다 길면 그 사이 시뮬 시간이 얼마나 흘렀는지 알 수 없다고 보고,
   파티클마다 0 ~ 간격(최대 `odom_gate_max_dt` 0.5 s) 사이의 시간을 따로 뽑아 그만큼 움직인다. 어느 쪽이 맞는지는 라이다 측정이 고른다.
   경고 로그 `odometry gap #N`.
4. 2, 3 의 메시지와 그 다음 메시지는 EKF 방향이 튀었다 돌아오는 중이라 방향 변화를 각속도 x 간격으로 쓴다.
5. 원래 방식(위치 차이)은 `odom_motion: pose` 로 쓸 수 있고, 이때는 위치 차이를 속도로 확인하는 점프 차단(`odom_gate`)이 적용된다.

파라미터: `odom_motion` (velocity | pose), `odom_clock_jump`, `odom_gap_dt` (0 = 끔), `odom_gate_max_dt`, `odom_gate`, `odom_gate_trans`, `odom_gate_rot`.
`svg_mppi_node` 쪽에도 같은 원인 대응이 있다: 위치 지연 보정(`pose_latency_comp`)이 위치의 나이를
(도착할 때의 지연 + 도착 후 흐른 시간, steady 시계)로 재서 시계 점프에 속지 않고, EKF 멈춤(~0.35 s)은 `pose_latency_max`(0.4 s)까지 예측한다.
실험 도구 `init_pf_pose.py` 는 시작 위치를 보낸 뒤 particle filter 추정이 1 m 안으로 들어왔는지 확인하고 아니면 다시 보낸다
(한 번은 초기 위치 메시지가 사라져 particle filter 가 14 m 떨어진 곳에서 시작했다).
